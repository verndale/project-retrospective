# Retrospective workflow — Design History

The analyze path: what a completed project is read for, how its labels are resolved, and what gates the output.

## Current state

- Deterministic scripts do the mechanical work. `inventory.cjs` pins Git HEAD and discovers ordinary single-package/workspace code from the root plus only manifests admitted by package workspaces or `pnpm-workspace.yaml`; unrelated nested packages cannot add platform markers or component roots. Exact framework/platform markers, conventional roots, imports, tests/stories/styles/tokens, consumers, and delivery configuration remain source evidence; pipeline artifacts are optional corroboration. Unsafe/traversal roots and source, delivery, workspace, artifact, or memory symlinks are warned and skipped because their target bytes are not pinned. `prior-evidence.cjs` selects valid recurrence. `resolve.cjs` matches labels against the brain manifest. Source-parity/capture and retrospective scripts own their respective structure, while `validate-report.cjs` remains the sanctioned run validator.
- Resolution is exact after normalization — lowercase, camelCase-boundary split, spaces and underscores collapsed to hyphens. No stemming, no plural folding, no nearest-match. A label resolves or it is novel.
- A label that maps to two canonicals through a context-scoped alias is reported `ambiguous` with its candidates; the script never picks. The model confirms from usage evidence or demotes the label to unresolved.
- The model's only job is judgment: triage into Promote / Watch / Reject with cited evidence, then draft prose. Verdicts carry evidence paths, never numeric scores.
- The validator runs under a stated cap of three attempts. On the third failure the run stops and reports the remaining failures verbatim rather than reshaping output to satisfy the validator.
- Captures are separate from proposals. Analyze holds report entries in two-way parity with lightweight pending intents only; structural identity types and default/variant/label/key relationships are exact. Selected intents gain source-parity, architecture, realization, and Figma planning at capture time after pinned-source verification — see [library capture](library-capture.md).
- The report's three downstream sections each pair with one artifact and one repo: `## Candidates` with `proposals/` for ui-design-brain, `## Captures` with `captures/` for ui-design-library, `## Learnings` with `orchestration-drafts.md` for ai-orchestration.
- Team retrospectives are an optional evidence source and an append-only backfill scope. Explicit pages are included, automatic discovery stays inside seeded spaces, and every candidate is reconciled as included or excluded. Retrospective evidence can affect component triage only when it names an inventoried component and agrees with strong non-code-scan as-built evidence.
- Retrospective actions receive stable IDs, a destination, owner, next step, and lifecycle state. Missing owners escalate to `needs-owner`; `done` needs proof and `wont-do` needs rationale. Raw pages, people, and issue links stay in the private evidence repo, while shared-repo work moves only through client-neutral proposals, captures, and orchestration drafts.
- `tracking-targets.cjs` deterministically separates skip, issue-pending, and write-ready targets. Analyze branches only evidence; promote branches brain only after approval and a non-empty write set; capture `enrichment-pending` can prepare only evidence after writer/live proof, while schema-v6 `ready` alone can authorize actionable library writes. An executable branch name is withheld while authentication, labels, issue identity, clean main, alignment, or required capability is unresolved.
- Governed targets file or reuse exact open issues automatically with sanctioned labels. This does not authorize commits, pushes, PRs, closure, Figma publication, merging, or releases.
- CMS identity comes from a deterministic seven-entry catalog. Inventory emits `config.cmsKey`/`config.cmsLabel`; `meta.json` and the report repeat the exact pair, and validation rejects legacy or mismatched values.
- Catalog recognition does not grant discovery capability. Contentstack, Optimizely SaaS, and SitecoreAI retain dedicated CMS profiles; the other canonical CMS identities use the broad fallback with an explicit capability warning, while `toolkit` remains a supported non-CMS profile.
- Platform inference accepts only exact dependency/config markers from admitted workspace manifests or a canonical override; competing exact markers stay null. Code plus colocated tests/stories/styles/consumers is one project implementation family, never multiple promotion sources.
- Prior evidence requires a real owned `runs/` root, non-symlink project/run/artifact surfaces, real ISO calendar dates rather than merely date-shaped strings, exact canonical-or-null platform parity across inventory/meta/report, and ordinary (not retrospective-only) scope before lexical latest-run selection can consider it.
- Cross-project recurrence uses the latest eligible run per other project, includes Watch and Promote, excludes Reject, and validates identity/resolution joins. `Data` supplies runs automatically; `PriorReports` is a functional explicit escape hatch for eligible reports outside `Data` or without `Data`. Both sources enter one latest-per-project merge, so stale explicit paths warn and cannot override newer evidence.
