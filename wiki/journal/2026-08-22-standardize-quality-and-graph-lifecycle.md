# Standardize quality and graph lifecycle

## Why

- Local commits, pushes, and pull requests did not expose one consistent lint/test contract.
- Commitlint used the same policy through different engines and a private package path, leaving room for local/CI drift.
- A pre-commit rebuild could describe unstaged input and accidentally stage generated bytes outside the intended commit.

## What changed

ESLint now owns first-party JavaScript linting: staged files are fixed before commit, the stable Node suite blocks pushes, and one non-mutating quality job adds the full graph check in CI. The pre-push hook clears Git's repository-local environment before running tests so temporary fixture repositories cannot affect the contributor checkout. The viewer is linted as browser-only code instead of inheriting Node globals from repository scripts. Commitlint consumes the public shared preset through one root config and remains a separate title/range governance job. Wiki reminders and graph rebuild/staging stay advisory, skip unstaged input, and fail open; CI performs only check-mode validation. A typecheck gate was ruled out because the repository has no first-party TypeScript implementation.
